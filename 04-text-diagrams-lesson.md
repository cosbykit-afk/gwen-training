# Lesson 3 (skeleton) — Text-based ER and systems diagrams

**Objective.** Learn to read and write diagrams as *text* — no images.
Text diagrams can be read aloud, searched, versioned, and checked line by
line, which makes them the right tool for your work.

## Questions to answer from your approved sources and example material

1. **ER diagrams.** What is an entity? What is an attribute? What is a
   primary key, a foreign key? What do the relationship lines mean
   (one-to-many, many-to-many)? How is "this can be empty" shown?
2. **Systems diagrams.** What is a system context (level 0) diagram — what
   is inside the box, what is outside it? What do the arrows between boxes
   mean? What changes when you go one level deeper?
3. **Text rendering.** How do you draw a box-and-arrow diagram using only
   text characters so that another reader (or model) reconstructs the same
   picture?

## Example material (prepared with this lesson)

Text-based renderings of Lampy's own diagrams — the forum database ER
diagram and the Lampy system diagrams, drawn as text. You will study the
real systems you administer, not toy examples.

*(The text renderings are prepared as part of building this lesson —
currently the Lampy diagrams exist as images; text versions follow.)*

## Hands-on tasks

1. In your own words, describe what the forum ER diagram says: the tables,
   their keys, and how they connect.
2. Draw a text diagram of one part of the Lampy stack (your choice which
   part) and explain every box and arrow in it.

## Done when

Your descriptions match the actual database schema and the actual running
services (Muse will check), and your text diagram is unambiguous enough
that Muse can redraw it without asking you a question.
